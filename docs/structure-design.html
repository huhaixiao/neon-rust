分工一句话
world/ 只有“拼装”：主场景与地图，不放玩法逻辑
systems/ 全场范围的服务：波次、相机、爆发特效
entities/ 可被实例化的东西：玩家、敌人、子弹、拾取物
core/ 全局状态与数据模板，不含具体内容
命名：文件 snake_case；节点 PascalCase；场景与脚本同名同目录；数值资源用 _stats.tres。

5 · 风险与刻意不做的事

迁移风险
· .uid 必须随 .gd 一起搬，否则脚本引用断
· .tscn 里的 ext_resource 是路径引用（不是 uid），shell mv 后必须重写
· project.godot 的 3 个 autoload 路径要同步改
· SAVE_PATH = user://neon_rust.cfg 不变，最高分不会丢
· 输入 action 名不变，Deck 手感不受影响
· exclude_filter 仍排除 docs/tools/tests，打包体积不变
刻意不做
· 不新增 Events autoload —— 现有 7 个 Game 信号够用，多一个总线只是换个名字
· 不给每种敌人单开目录 —— 3 个文件不值得再套一层
· 不上 ECS / 不把 core 拆成一堆 autoload
· 不在 P1 阶段动任何玩法代码，先证明“搬迁无副作用”
如果只想改善体验、不想大动：做完 P1+P2 就够，P3 之后属于“加内容前的前置投资”。
核对数据：引用面 = 11 处 res://scripts/*.gd + 17 处 res://scenes/*.tscn + 3 个 autoload 路径；当前 0 个 .tres、12 个目录。设计稿不动代码，等你确认再开工。
